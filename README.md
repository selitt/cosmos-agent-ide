# Cosmos Agent IDE

Локальное приложение для macOS: редактор Python, Codex, Gemini CLI и команда агентов с деревом должностей.

## Запуск на Mac

1. Откройте `dist/Cosmos Agent IDE.app` (или распакуйте ZIP из Releases).
2. Выберите рабочую папку. Переключение проекта: **Файл → Открыть папку…**.
3. Откройте или создайте `.py` файл; **⌘S** сохраняет, **⌘Enter** запускает.
4. В **Настройках** выберите Python-интерпретатор, при необходимости модель; Gemini подключите кнопкой входа через консоль.

Приложение использует установленный **Python 3.10+**. Если есть `.venv/bin/python` в проекте, он выбирается для запуска скриптов. Интерпретатор сервера можно задать переменной `COSMOS_PYTHON` при запуске .app из терминала. Сборка ARM64 предназначена для Apple Silicon; на Intel соберите приложение из исходников.

Сборка имеет локальную ad-hoc подпись, без Apple Developer ID и notarization. Это прототип для локальной разработки, не версия из App Store.

## Запуск из исходников

Дополнительные Python-пакеты и npm-зависимости не нужны:

```sh
python3 server.py /path/to/your/project
```

Сервер открывает браузер и слушает только `127.0.0.1`. Для выбора свободного порта:

```sh
python3 server.py /path/to/project --port 0
```

Не публикуйте локальный сервер в интернет. Ссылка запуска содержит токен доступа к файлам и запуску кода.

## Codex

Нужен рабочий Codex CLI с авторизацией `codex login`. Cosmos ищет CLI в `CODEX_BINARY`, затем в PATH, затем в установленном ChatGPT.app. Данные авторизации остаются у CLI; Cosmos не читает и не копирует ключи из файлов авторизации.

По умолчанию чат работает в sandbox `read-only`. Флажок **Codex может изменять файлы проекта** включает `workspace-write`; перед запросом открытые изменённые файлы сохраняются. После завершения чистые буферы перечитываются с диска. Изменения, сделанные вами во время запроса, сохраняются в редакторе, а проверка версии при сохранении предупреждает о конфликте.

Модель Codex можно оставить пустой — используются настройки CLI. Чат передаёт последние 16 сообщений и текущий файл, если включено его прикрепление.

[Официальная документация Codex CLI](https://learn.chatgpt.com/docs/developer-commands?surface=cli)

## Gemini через консоль Google

Начиная с 0.1.3 приложение предпочитает официальный Antigravity CLI (`agy`) для Gemini. Старый Gemini CLI может возвращать `UNSUPPORTED_CLIENT` при входе в Code Assist для физических лиц; повторная авторизация в нём не устраняет отказ Google.

1. Установите [Antigravity CLI](https://www.antigravity.google/docs/cli/install/).
2. Откройте **Настройки → Войти в Gemini через консоль**. Приложение запустит `agy` в Terminal; завершите Google-вход в браузере.
3. Вернитесь в IDE и выберите Gemini. API-ключ не требуется. По умолчанию запрашивается `gemini-3.8-flash-medium`; другую модель можно выбрать в настройках или для конкретной роли. Доступные имена: `agy models`.

CLI использует собственную сохранённую авторизацию. Cosmos не читает и не копирует OAuth-токены. Поддерживаются `AGY_BINARY`, PATH и `~/.local/bin/agy`. После установки перезапустите IDE. Чат и роли используют режим `plan`, поток JSON через stdin/stdout и отмену всей группы процессов. Ответ передаётся в чаты и отчёты команды. Доступ зависит от аккаунта, региона, сети и квот Google.

При отсутствии `agy` остаётся совместимость со старым Gemini CLI. Для входа через Google рекомендуется установить `agy`. Подробнее: [вход](https://www.antigravity.google/docs/cli/install/), [консольный протокол](https://www.antigravity.google/docs/cli/headless/).

## Команда агентов

Нажмите значок команды слева. В начальном дереве: руководитель, архитектор, Python-разработчик и тестировщик.

- До 12 должностей, один корневой руководитель, произвольная вложенность.
- У каждой роли: имя, должность, руководитель, Codex/Gemini, модель и инструкции.
- Конфигурация сохраняется в `.cosmos-ide/team.json` выбранной рабочей папки.
- Общая задача и инструкции руководителей передаются исполнителям; независимые ветви работают параллельно, максимум 3 вызова AI одновременно в одной команде.
- После завершения подчинённых их непосредственный руководитель получает отчёты и формирует свой результат. Корневой руководитель готовит итог.
- Ошибка одного агента видна в его карточке и в итоговом статусе. Остальные ветви продолжают работу.
- Отчёт каждой роли открывается кнопкой ↗. Codex в режиме команды работает `read-only`, поэтому параллельные агенты не перезаписывают общий проект.

Это выполнение дерева **снизу вверх**, а не автономная генерация дерева задач руководителем. Дерево и зоны ответственности задаёт пользователь. Чаты и отчёты текущего запуска хранятся в памяти и очищаются при закрытии.

Кнопка остановки завершает процессы Codex, Gemini и Python; новые этапы команды после отмены не стартуют.

## Редактор

Дерево файлов, вкладки, подсветка Python, отступы по Tab/Enter, поиск ⌘F, номера строк, сохранение с проверкой конфликта и вывод stdout/stderr. Файлы — UTF-8, до 1 МБ. Запуск выполняется из корня открытой рабочей папки. Выполнение Python локальное, с обычными правами пользователя.

Вывод программы не является интерактивным терминалом: `input()` сейчас не поддерживается. Пока нет LSP-автодополнения, отладчика и интеграции Git в интерфейсе. Python-подсветка лексическая, без полного AST.

## Сборка и тесты

Нужны macOS и Xcode Command Line Tools:

```sh
bash scripts/build_macos.sh
python3 -m unittest discover -s tests -v
node --check web/app.js
```

Сборка создаёт `.app` и ZIP в `dist/`. При необходимости SDK задаётся через `COSMOS_SDK_PATH`. Нативное окно — Cocoa/WKWebView; Python-сервер автоматически запускается на свободном loopback-порту и останавливается при выходе.

Тесты проверяют файловые конфликты, выход за рабочую папку и симлинки, отмену процессов, HTTP-аутентификацию и Origin, протокол Gemini, парсинг Codex и параллельную иерархию агентов. Сетевые вызовы Gemini в тестах заменены заглушкой: для живой проверки нужен выполненный Google-вход в консольном клиенте.

### Gemini: команды в фоновом режиме (0.1.4)

Чат и роли Gemini используют профиль `.agents/agents/cosmos-ide-review.md` с инструментами `view_file` и `grep_search`: читают код и возвращают предложения, без запуска команд и записи файлов. Профиль создаётся в открытом проекте; существующий файл с другим содержимым не перезаписывается. Для выполнения Python используйте кнопку «Запустить». Глобальные разрешения Antigravity не изменяются. Отказ инструмента больше не предлагает повторный Google-вход и не дублирует диагностический текст.

## Инструменты разработки (0.2.0)

- Меню проекта имеет отдельную вертикальную прокрутку с видимым скроллбаром.
- Подсказки Python появляются при вводе. `Ctrl+Space` открывает список, ↑/↓ выбирают вариант, Enter/Tab вставляют, Esc закрывает. Доступны ключевые слова, встроенные функции, имена из открытого файла, сигнатуры объявленных функций и методы стандартных типов. Анализ локальный, без запуска кода; полноценный LSP и подсказки сторонних библиотек пока не включены.
- Вкладка **Терминал** открывает shell в папке проекта. Команды и состояние окружения сохраняются в сеансе. Есть Ctrl+C, Ctrl+D, перезапуск и прямой ввод при фокусе на области вывода. Это текстовый терминал; полноэкранные TUI (vim, top) и отрисовка ANSI не поддерживаются.
- **Запустить** сохраняет открытые файлы и выполняет активный `.py` через выбранный Python. Поле «Аргументы» принимает параметры с кавычками. Ввод для `input()` доступен под выводом. «Стоп» завершает процесс.
- Нажмите номер строки, чтобы поставить/снять точку остановки. **Отладка / F5** запускает файл и останавливается перед первой строкой. F5 продолжает до точки остановки, F10 выполняет шаг, F11 входит в функцию, Shift+F11 выходит. Панель показывает локальные переменные и стек; на кадр стека можно нажать. Есть пауза, остановка, ввод `input()` и просмотр необработанного исключения. Пока поддерживается отладка Python в главном потоке; подпроцессы и C-расширения не отлаживаются. Во время отладки редактор доступен для чтения.

Терминал, запуск и отладчик работают локально и запускаются действиями пользователя. Сеансы закрываются вместе с IDE или при смене папки. Эти инструменты не выдаются AI-агентам автоматически. Авторизация HTTP-запросов и привязка сервера к loopback сохранены.
